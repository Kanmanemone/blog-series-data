# Data Model: 배치 결정 파일 제거

## Series File (`<seriesId>_series.json`) — 유일한 기준

스키마 변경 없음(Constitution I).

| 필드 | 설명 |
|---|---|
| `listName` | 시리즈 이름. 새 파일은 공개 시각이 가장 이른 글의 원시 시리즈명. 이후 봇은 바꾸지 않는다. |
| `items[]` | `{ title, url }`. 순서는 파일에 적힌 그대로가 정답. |

### 봇이 하는 편집(이 외에는 파일을 바꾸지 않음)

| 연산 | 효과 | 순서 영향 |
|---|---|---|
| appendBatch | 없는 URL만 끝에 붙임, 묶음 안은 공개 시각 순(모르면 뒤) | 기존 항목 불변 |
| retitleItem | 같은 위치에서 title만 교체 | 없음 |
| removeItem | 해당 URL 항목 제거 | 나머지 상대 순서 불변 |
| 파일 삭제 | 이번 실행에 손댄 파일의 items가 1개 이하면 파일 삭제 | — |
| 새 파일 생성 | 2개 이상인 묶음으로 생성, 묶음 안은 공개 시각 순 | — |

## Processed Post (`.github/sync-state.json` `processedPosts[]`) — 변경 없음

`url, title, lastMod, publishedAt, processedAt, deletedAt?` (구 레코드는 `rawSeriesName`). `publishedAt`은 묶음 정렬에 쓰인다.

## Series Assignment (`.github/series-assignments.json`) — 삭제

## 불변식

- **INV-1 (004 INV-3 유지)**: 모든 목차 항목의 제목 = 같은 URL 처리 이력의 `title`(레코드에 title이 있을 때).
- **INV-2 (신규, 004 INV-2 대체)**: 한 URL은 최대 한 목차에만 있다.
- **INV-3**: 봇이 실행 전후로 남겨 둔 두 항목의 상대 순서는 같다.

## 커밋 요약 카테고리 매핑

| 사건 | 카테고리 |
|---|---|
| 기존 파일에 붙임(신규·이동) | 시리즈 - 항목 추가 (파일당 붙인 개수) |
| 새 파일 생성(001 또는 재분류) | 시리즈 - 생성 (파일당 1) |
| 기존 파일에서 뺌, 파일은 남음 | 시리즈 - 항목 제거 |
| 제목 그 자리 변경, 파일은 남음 | 시리즈 - 제목 갱신 |
| 손댄 파일이 1개 이하가 되어 삭제 | 시리즈 - 삭제 (그 파일의 추가/제거/제목 갱신은 세지 않음) |
| 시리즈 없음·2개 미만 신규 글 | 게시글 - 새 글 |
| 제목 그대로 재확인, 목차 밖 글 재확인 | 게시글 - 정보 갱신 |
| 목차 밖 글의 삭제 확정 | 게시글 - 삭제 |
